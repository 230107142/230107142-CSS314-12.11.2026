### Analysis

The stride sweep shows relatively small performance differences.
Stride 16, corresponding to 128 bytes, achieved a median
execution time of 473.272 ms, compared with 479.635 ms
for stride 1.

This suggests that separating worker variables by the
reported cache-line size may reduce false sharing.
However, the improvement was only approximately 1.33%,
so cache coherence contention was not a dominant
performance bottleneck in this experiment.

## 4. Task 3: Diagnostic Analysis

The experiment demonstrates that increasing the number of
processes improves performance, but the speedup is not
linear. With eight processes, stride 1 achieved a speedup
of 4.068, while stride 16 achieved 4.133.

The Karp-Flatt serial fraction increased as the process
count increased, indicating growing parallel overhead.

stride 1, suggesting that cache-line separation can help
reduce memory contention.

However, the small difference between the two strides
indicates that false sharing was not the only factor
affecting performance. Process creation, synchronization,
and other system overheads may also contribute.

This may be related to the Apple M2's heterogeneous processor architecture, which contains four performance cores and four efficiency cores.
